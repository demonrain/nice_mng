# 二期需求文档（Phase 2 Roadmap）

> 基于一期（RBAC、动态菜单、监控、定时任务、代码生成、低代码表单、多数据源）的能力，本文规划二期可扩展功能、优先级与验收标准，供后续迭代选择实现。

## 1. 背景与目标

一期已交付一个功能完整、可部署的后台管理基座。二期目标：
- **企业级安全与合规**：补齐审计、多因素认证、密钥管理。
- **多租户与组织化**：支持 SaaS 化运营。
- **可观测性与稳定性**：日志/链路/告警闭环。
- **协作与流程**：工作流、消息中心、国际化运营。
- **开发提效**：插件机制、在线代码生成落盘、OpenAPI/SDK。

## 2. 需求清单（按优先级）

### P0 — 必做（安全 / 稳定基线）

> 状态：P0-1~P0-4 已在 `feature/phase2` 实现（详见 [security.md](./security.md)）；P0-5 待办。

| 编号 | 功能 | 说明 | 验收标准 | 状态 |
| --- | --- | --- | --- | --- |
| P0-1 | 多因素认证 MFA | TOTP（Google Authenticator）+ 备用码 | 开启后登录需二次校验；备用码一次性有效 | ✅ 已实现 |
| P0-2 | 审计与安全日志增强 | 登录异常检测（异地/多次失败锁定） | 连续失败 N 次锁定；异地登录记录 | ✅ 已实现 |
| P0-3 | 接口限流与防刷 | 基于 Redis 的 IP/用户级限流 | 超阈值返回 429；可配置规则 | ✅ 已实现 |
| P0-4 | 密码与会话策略 | 密码强度策略、强制下线、改密令牌失效 | 弱密码被拒；改密后旧 token 失效 | ✅ 已实现 |
| P0-5 | 数据库迁移规范化 | 引入 `prisma/migrations` 版本化迁移 + CI 校验（单一 provider） | 迁移可重放；CI 检测 schema 漂移 | ⏳ 待办 |

## 3. 重点需求详述

### 3.1 多租户（P1-1）

- **隔离方案对比**：
  - 行级隔离（共享库 + `tenantId`）：成本低、运维简单，需在 Prisma 查询统一注入租户过滤（中间件/`$extends`）。
  - Schema 级隔离：隔离强、迁移复杂。
  - 库级隔离：最强隔离，配合一期多数据源能力可扩展。
- **建议**：默认行级隔离 + 预留库级隔离接口（复用 `docs/database.md` 多数据源方案）。
- **改造点**：实体加 `tenantId`、登录态注入租户、全局查询过滤、超管跨租户视图。

### 3.2 工作流引擎（P1-2）

- 选型：自研轻量状态机 或 集成开源（如基于 BPMN）。
- 数据模型：流程定义、流程实例、任务、审批记录。
- 与现有 RBAC 打通审批人来源（角色/部门/岗位/指定人）。

### 3.3 消息中心（P1-3）

- 通道适配器接口：`send(channel, template, payload)`，通道可插拔。
- 复用一期 WebSocket 网关做站内实时；邮件用队列（BullMQ 已在依赖中）异步发送。

### 3.4 可观测性（P2-1）

- 替换 Nest 默认日志为结构化日志（pino），接入 OpenTelemetry。
- `/metrics` 暴露 Prometheus 指标，配合 Grafana 看板。

## 4. 非功能性需求

- 性能：核心列表接口 P95 < 200ms（缓存命中下）。
- 安全：通过常见 OWASP Top 10 自查；敏感配置脱敏。
- 兼容：继续保持 PostgreSQL/MySQL 双栈可切换。
- 可维护：新增能力遵循一期模块化与文档/记忆更新约定。

## 5. 里程碑建议

| 阶段 | 内容 | 周期(估) |
| --- | --- | --- |
| M1 | P0 全部（安全基线 + 迁移规范化） | 2~3 周 |
| M2 | P1-1 多租户 + P1-3 消息中心 + P1-4 存储抽象 | 3~4 周 |
| M3 | P1-2 工作流 + P1-5/6 国际化与导入导出 | 3~4 周 |
| M4 | P2 体验/可观测/提效项按需排期 | 滚动 |

## 6. 风险与依赖

- 多租户改造涉及全量查询过滤，需在早期统一封装，避免后期返工。
- 迁移规范化与多 provider 切换存在张力：迁移文件 provider 特定，建议生产固定单一 provider，开发态保留 `db push` 灵活性。
- 工作流与消息中心引入异步队列，需补充 Redis/队列的容量与监控。
