# 使用教程

面向使用者与二次开发者的上手教程。部署细节见 [deployment.md](./deployment.md)，数据库切换见 [database.md](./database.md)。

## 一、启动并登录

1. 按 [deployment.md](./deployment.md) 启动（Docker 或本地）。
2. 浏览器打开 `http://localhost:8080`（本地开发为 `http://localhost:5173`）。
3. 用默认账号登录：`admin / admin123`，输入图形验证码后进入。
4. 接口文档：`http://localhost:8080/api/docs`（Swagger）。

## 二、界面导览

- **左侧菜单**：按当前账号权限动态生成；可折叠。
- **顶部栏**：折叠按钮、面包屑、消息铃铛（站内信未读数 + 列表）、设置齿轮（系统设置抽屉）、语言切换、用户头像（个人中心 / 退出）。
- **系统设置抽屉**（点顶部齿轮）：暗黑模式、主题色预设、导航布局（侧边 / 顶部 / 混合）、紧凑模式；偏好自动本地持久化。
- **仪表盘**：统计卡片 + 访问趋势/占比图 + 最新公告。

## 三、常见操作

### 1. 新建一个用户并授权

1. `系统管理 → 用户管理 → 新增`，填写用户名、密码、部门、角色。
2. 角色决定其菜单与按钮权限；部门配合角色的数据权限决定可见数据范围。

### 2. 配置角色与权限

1. `系统管理 → 角色管理 → 新增`。
2. 勾选「菜单权限」树（目录/菜单/按钮三级，按钮即细粒度操作权限）。
3. 选择「数据权限」：全部 / 本部门 / 本部门及以下 / 仅本人 / 自定义部门。

### 3. 维护菜单与按钮权限

1. `系统管理 → 菜单管理`。
2. 新增「菜单」时填 `路由路径` 与 `组件路径`（如 `system/user/index`）。
3. 在该菜单下新增「按钮」子项，填权限标识（如 `system:user:add`），即可被前端 `<Access>` 与后端 `@RequirePermissions` 使用。

### 4. 字典 / 参数配置

- `系统管理 → 字典管理`：左侧选类型，右侧维护键值（供下拉、标签展示，带缓存）。
- `系统管理 → 参数配置`：维护全局参数（如系统名称、是否启用验证码）。

### 5. 系统监控与定时任务

- `系统监控 → 服务监控`：CPU/内存/磁盘/Redis 实时指标（5s 刷新）。
- `系统监控 → 在线用户`：查看在线会话，可「强退」。
- `系统监控 → 定时任务`：新增任务选择处理器(如 `cleanLoginLog`)、填 cron；支持「执行一次」「暂停/运行」「查看执行日志」。

### 6. 通知公告与实时推送

- `系统管理 → 通知公告`：新增公告后点「广播」，所有在线用户会收到 WebSocket 弹窗通知。

## 四、低代码与代码生成

### 1. 表单设计器（零代码做表单）

1. `系统工具 → 表单设计器 → 新建`。
2. 左侧点选组件加入画布，中间排序/删除，右侧配置标签、必填、栅格、选项。
3. 底部「实时预览」即所见即所得，保存后通过编码复用（`formApi.byCode`）。

### 2. 代码生成器（快速搭业务模块）

1. `系统工具 → 代码生成 → 新增`，填表名、实体类名、模块名、业务名、功能名，并编辑字段（类型/控件/必填/是否列表/是否表单）。
2. 点「预览代码」，得到 Prisma model、后端 dto/service/controller、前端 api 与页面代码。
3. 点「生成代码」可直接落盘到工程 `apps/api/generated/<模块>_<业务>/` 目录（不会覆盖 `src`），再复制到对应目录并按 [extension-guide.md](./extension-guide.md) 接线（注册模块 + 配置菜单）。

## 五、二期功能使用

> 以下功能对应菜单需先以空库执行种子（或在「菜单管理」手动补充）。完整接口/数据模型见 [phase2-features.md](./phase2-features.md)。

### 1. 租户管理（多租户）

- `系统管理 → 租户管理`：新增/编辑租户（名称、标识 code、联系人、到期时间、状态）。
- 行级隔离需设环境变量 `TENANT_ENABLED=true`；新建用户时归属某租户后，业务数据可按租户隔离（超管跨租户可见）。

### 2. 工作流（审批）

1. `工作流程 → 流程定义 → 新增`：填流程名、编码，并在「审批节点」填 JSON，例：
   `[{"key":"lead","name":"主管审批","assigneeId":1},{"key":"hr","name":"HR审批","assigneeId":2}]`（按数组顺序逐级审批）。
2. 发起流程：通过接口 `POST /api/workflow/start`（或在业务页接入），传 `defCode`、`title`、`formData`。
3. `工作流程 → 我的待办`：处理分配给自己的任务，点「通过 / 驳回」并填意见；通过则流转到下一节点，最后一节点通过即审批完成，驳回则整单驳回。
4. 每一步会通过站内信/WebSocket 通知相关人；发起人会收到最终结果通知。

### 3. 消息中心

- `系统管理 → 消息中心 → 消息模板`：维护模板（编码、通道、标题/内容，内容支持 `{{变量}}` 占位）。
- `发送消息` 标签页：选择通道（站内信 / 邮件 / 短信 / Webhook），填标题内容，目标用户 ID 逗号分隔（留空=全员）发送。
- 顶部「铃铛」实时显示未读站内信，可点开查看、单条已读或「全部已读」。
- 邮件/Webhook 通道需在 `.env` 配置 `MAIL_*` / `MSG_WEBHOOK_URL`，未配置时自动安全降级（仅记录日志）。

### 4. 国际化（多语言运营）

- `系统管理 → 国际化`：新增词条（语言 `zh/en`、命名空间、键如 `common.search`、文案），支持按语言筛选与搜索。
- 前端切换语言时会自动从后端拉取词条并合并，**新增/修改文案无需重新发版**（拉取失败则回退内置词条）。

### 5. 用户数据导入 / 导出

- `系统管理 → 用户管理`：
  - 「导出」：按当前数据权限导出用户为 xlsx。
  - 「导入」：先下载「导入模板」，按模板填写后上传；用户名为必填，缺失行会在结果中回显错误，导入用户默认初始密码 `123456`。

### 6. 文件存储

- `系统管理 → 文件管理`：上传/查看/删除文件，列表记录文件所在存储后端。
- 默认本地磁盘存储；切换对象存储设 `STORAGE_DRIVER=oss/s3/minio` 并在 `storage.service.ts` 接入对应 SDK（详见 phase2-features.md）。

### 7. 数据报表 / 数据大屏（BI）

1. `系统管理 → 数据报表 → 新增`：填名称、编码，勾选「设为默认」，在「布局配置」填组件 JSON，例：
   `[{"type":"stat","title":"用户数","value":128,"span":6},{"type":"line","title":"趋势","span":12,"x":["一","二","三"],"series":[10,20,15]}]`
   组件类型支持 `stat / line / bar / pie`，`span` 为栅格宽度（24 栅格）。
2. `数据大屏`菜单会渲染「默认」仪表盘的所有卡片。

### 8. 个性化主题与布局

- 点顶部齿轮打开「系统设置」：切换暗黑模式、主题色、导航布局（侧边/顶部/混合）、紧凑模式，设置会自动保存到本地。

### 9. 可观测性（运维）

- Prometheus 指标：`GET /api/metrics`（建议经网关/白名单保护）。
- 指标概览（健康看板用）：`GET /api/monitor/metrics/summary`。
- 生产环境（`NODE_ENV=production`）日志输出为单行 JSON，便于 ELK/Loki 采集。

## 六、二次开发速查

| 我想… | 去哪做 |
| --- | --- |
| 加一个后端接口模块 | `apps/api/src/modules/`，注册到 `app.module.ts`，详见 extension-guide |
| 加一个前端页面 | `apps/web/src/pages/`，在菜单管理配置 component |
| 加按钮权限 | 菜单管理加 BUTTON + 角色授权；前端 `<Access perm="...">`，后端 `@RequirePermissions('...')` |
| 换数据库(MySQL) | 见 database.md（设 `DB_PROVIDER` + `DATABASE_URL`） |
| 加定时任务 | `job.handlers.ts` 注册处理器 + 后台配置 |
| 改全局响应/异常 | `apps/api/src/common/interceptors|filters` |
| 改主题/品牌色 | `apps/web/src/store/app.ts` 与 `App.tsx` 的 ConfigProvider |
| 业务表按租户隔离 | 表加 `tenantId Int?`，查询用 `tenantWhere()`；设 `TENANT_ENABLED=true` |
| 关闭某二期模块 | 设 `DISABLED_MODULES=WorkflowModule,...`（见 plugin.md） |
| 接入对象存储 | `apps/api/src/modules/file/storage.service.ts` 实现适配器 |
| 生成前端 SDK | `pnpm --filter @nice-admin/api gen:sdk`（先启动一次导出 openapi.json） |

## 七、默认数据

种子脚本(`apps/api/prisma/seed.ts`)会创建：超级管理员 `admin`、普通角色、总公司部门、岗位、全量菜单与按钮、通用状态/性别字典、系统参数、欢迎公告。
